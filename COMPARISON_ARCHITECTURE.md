# Архитектура механизма сравнения фильтров

## Общая концепция

Реализовать возможность сравнения двух наборов фильтров на одной странице:
- **Основной фильтр** - текущий набор фильтров (как есть сейчас)
- **Фильтр для сравнения** - второй набор фильтров с префиксом `compare_`
- При активации режима сравнения (`compare=1`) отображаются оба набора данных рядом

## 1. Backend (views.py)

### 1.1 Параметры запроса

**Основной фильтр** (как сейчас):
- `date_start`, `date_end`
- `report_type`
- `unit_source_ids`, `unit_ids`, `city_ids`, `type_reception_ids`, `brands`

**Фильтр для сравнения** (новые параметры с префиксом `compare_`):
- `compare_date_start`, `compare_date_end`
- `compare_report_type`
- `compare_unit_source_ids`, `compare_unit_ids`, `compare_city_ids`, `compare_type_reception_ids`, `compare_brands`
- `compare=1` - флаг активации режима сравнения

### 1.2 Логика обработки

1. **Парсинг параметров**:
   - Парсим основной фильтр (как сейчас)
   - Если `compare=1`, парсим параметры с префиксом `compare_`
   
2. **Выполнение запросов**:
   - Выполняем запрос для основного фильтра (как сейчас)
   - Если `compare=1`, выполняем аналогичный запрос для второго фильтра
   - Получаем два набора данных: `params` и `params_compare`

3. **Структура данных для сравнения**:
   ```python
   params = {
       'totals': {...},  # Основной фильтр
       'badges': {...},
       'type_reception_stats': [...],
       ...
   }
   
   params_compare = {
       'totals': {...},  # Фильтр для сравнения
       'badges': {...},
       'type_reception_stats': [...],
       ...
   }
   ```

4. **Передача в шаблон**:
   ```python
   return render(request, 'lo/tradein_funnel_analytics.html', {
       'params': params,
       'params_compare': params_compare if compare_mode else None,
       'compare_mode': compare_mode,
   })
   ```

### 1.3 Оптимизация

- Использовать один и тот же код для обоих запросов (вынести в функцию)
- Кэшировать справочники (units, cities и т.д.) - они одинаковые для обоих фильтров

**Графики**:
- Разбить один график на 7 отдельных графиков (по одному для каждого события)

### 2.3 Графики

**Структура**:
- 7 отдельных графиков вместо одного
- Каждый график в отдельном `kors-panel`
- Две линии на каждом графике:
  - Основной фильтр: синий цвет
  - Фильтр для сравнения: оранжевый/красный цвет

**События для графиков**:
1. РЛ (date_rlk)
2. Оценка (date_start_estimation)
3. Дистанционно (date_remote_success)
4. До КД (date_before_success)
5. Диагностика (date_diagnostic_success)
6. После КД (date_after_success)
7. Принято (date_reception_success)

### 2.4 Сворачиваемые секции

При активации режима сравнения:
- Все сворачиваемые секции (статистика по оценщикам, аналитикам, брендам) должны быть свернуты по умолчанию
- Можно добавить кнопку "Развернуть все" / "Свернуть все"

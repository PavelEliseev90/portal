Приложение: register

Назначение приложения: хранение и сопровождение доменных сущностей оценки/ценообразования/диагностики (семейство Reg*), плюс сервисные API для справочника диагностики и блок массовой переоценки автомобилей.

Карта моделей (ядро register.models)

1) Интерактивная оценка — страничные сущности

  • RegInteractivOcenka — главная сущность оценки.
  • OneToOne-страницы: RegInteractivOcenkaRemote, ...Document, ...Salon, ...Vnesh, ...Complectnost, ...Kolesa, ...TestDrive, ...Proverki, ...Soglasovanie.
  • RegInteractivOcenkaRLK — агрегат/связка оценки с рабочим листом.

2) Дополнительные модели внутри процесса оценки

  • RegInteractivOcenkaPrice — история ценовых изменений в контуре оценки.
  • RegInteractivOcenkaOptions — опции/конфигурация в оценке.
  • RegRegInteractivOcenkaFiles — файлы интерактивной оценки (фото/медиа по элементам).
  • RegInteractivOcenkaTask, RegInteractivOcenkaEmailPush, RegInteractivOcenkaHistoryOpens — задачи/уведомления/история просмотра.
  • RegInteractivOcenkaKorsStore, RegInteractivOcenkaKorsStoreSale — сущности по складским/продажным данным в контуре оценки.

3) Модели для 2КК (второго комплекта колес)

  • RegInteractivOcenkaKolesa.kolesa2_estimation — признак/значение наличия второго комплекта на этапе оценки.
  • RegInteractivOcenkaKolesaReception — факт приёмки 2КК (привязан к RegInteractivOcenka и DocRLK).
  • RegRegInteractivOcenkaFilesKolesaReception — файлы приёмки 2КК, FK на kolesa_reception.

4) Модели диагностического справочника

  • DiagnosticReferenceCategory — категория дефектов/диагностики.
  • DiagnosticReferenceItem — конкретный элемент внутри категории.
  • DiagnosticReferenceSelection — факты выбора диагностических пунктов.

5) Модели переоценки авто

  • RegCarsRepricingHistory — “шапка” запуска переоценки (статус, счётчики, ошибки).
  • RegCarsRepricingLog — логи по каждому авто в рамках запуска.
  • RegRefCarsOrganizationsPrice, RegRefCarsOrganizationsCalculationPrice, RegEstimationRefCarsOrganizations — связанные реестры цен/расчётов, используются в ценообразовании и аналитике.

Функции и логика (register/views.py)

diagnostic_reference_api(request)

  • Проверяет GET-параметр category.
  • Ищет активную DiagnosticReferenceCategory по code.
  • Возвращает JSON категории + список активных DiagnosticReferenceItem (отсортированы по order/title).
  • Коды ответов: 400 (нет category), 404 (категория не найдена), 500 (ошибка).

diagnostic_reference_stats(request)

  • Формирует агрегированную статистику:
    • по категориям (число элементов/использований),
    • топ элементов по использованиям,
    • сводка DiagnosticReferenceSelection по category_code.
  • Возвращает JSON-структуру для дашборда/аналитики диагностики.

Функции и логика (register/views_repricing.py)

repricing_list

  • Читает фильтры: search/unit/status/evaluation.
  • Строит queryset RegCarsRepricingHistory с фильтрами и пагинацией.
  • Подгружает справочники подразделений и вариантов оценки.

repricing_history_detail

  • Загружает конкретную запись истории и её логи (RegCarsRepricingLog), делает пагинацию логов.

repricing_run

  • Получает параметры запуска (unit/evaluation), создаёт CarsRepricingService.
  • Запускает run_repricing(user=request.user), пишет flash-messages по результату.
  • Редиректит в детализацию истории.

repricing_units

  • Собирает список подразделений и краткую статистику по предыдущим запускам.

repricing_preview_cars

  • AJAX-метод предпросмотра выборки автомобилей для будущего запуска.
  • Использует CarsRepricingService.get_cars_for_repricing(), отдаёт первые 100 в JSON.

Сервис переоценки (register/services_repricing.py)

CarsRepricingService.get_cars_for_repricing

  • Базовая выборка: RefCarsOrganization(quantity__gt=0).
  • Опциональные фильтры по подразделению и варианту оценки.

CarsRepricingService.calculate_car_price

  • Сейчас заглушка (TODO): возвращает old_price как new_price.
  • Предполагается, что здесь будет пользовательская логика расчёта цены.

CarsRepricingService.run_repricing

  • Создаёт RegCarsRepricingHistory(status='processing').
  • Проходит по авто и для каждого:
    • либо пишет error в RegCarsRepricingLog,
    • либо обновляет цену авто и пишет success,
    • либо пишет skipped, если цена не изменилась.
  • Заполняет итоговые счётчики и финальный статус (success/partial/error).

Где используется register (связки с другими приложениями)

  • estimations: использует ключевые модели интерактивной оценки и новую логику 2КК приёмки.
  • eco: активно использует диагностические справочники/селекции и ряд моделей оценки.
  • avtosalon: использует ценовые и расчётные модели RegEstimationRefCarsOrganizations, RegRefCarsOrganizationsPrice, RegRefCarsOrganizationsCalculationPrice.
  • admin: значительная часть моделей register зарегистрирована в Django Admin для ручного сопровождения.

Примечание по полноте

В приложении register очень большой объём моделей и полей. Здесь зафиксирован архитектурный срез и ключевые функции/связи. В следующем шаге могу сделать для register отдельную “табличную энциклопедию” по всем классам (модель → ключевые поля → FK/OneToOne → где читается/пишется).

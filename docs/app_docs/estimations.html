Приложение: estimations

Назначение: страницы интерактивных оценок (осмотр/карточки этапов), а также часть логики и endpoint-ов, связанных с формированием/проведением оценок. В этом документе подробно разобран ключевой функционал, который сейчас в работе: приёмка второго комплекта колёс (2КК).

Модели и связи, необходимые для 2КК

Ключевая сущность: оценка интерактивная

  • register.models.RegInteractivOcenka — основная сущность интерактивной оценки (связана с DocRLK через rlk_id косвенно в этом модуле).
  • Внутри оценки есть page_kolesa (OneToOne) с данными по колёсам.

Данные 2-го комплекта колес (в оценке)

  • register.models.RegInteractivOcenkaKolesa — страница колёс.
  • Ключевое поле: kolesa2_estimation — индикатор/количество “второго комплекта колес / оценка со 2КК”.

Приёмка второго комплекта колес (в отдельной сущности)

  • register.models.RegInteractivOcenkaKolesaReception — отдельная “приёмка” 2КК.
  • Связи:
    • estimation — FK на RegInteractivOcenka (какая оценка породила приёмку).
    • rlk — OneToOne на DocRLK (рабочий лист).
    • Справочники резины/дисков (mark_tyre/width_tyre/radius/season/disk_type + ET/DIA/PSD + количества).

Файлы приёмки (картинки/файлы)

  • register.models.RegRegInteractivOcenkaFilesKolesaReception — файлы, привязанные к конкретной приёмке 2КК.
  • Связь: kolesa_reception FK на RegInteractivOcenkaKolesaReception.
  • Хранит: file, file_mini, метаданные (name/comment/type_point/кординаты и т.п.).

2КК: полный “сквозной сценарий” (лист → создать/открыть → редактирование → файлы)

1) Список: kolesa_reception_list

Что делает: формирует пагинированный список оценок и показывает, есть ли приёмка 2КК и указан ли 2-й комплект в оценке.

Логика запроса (где/как выбираются данные)

  • Берёт базовую выборку: RegInteractivOcenka с select_related на поля, нужные для вывода (status, rlk, unit, page_kolesa, modification…).
  • С помощью Exists проверяет: существует ли RegInteractivOcenkaKolesaReception для этой оценки.
  • С помощью Subquery подтягивает reception_id (первый найденный id приёмки).
  • Применяет фильтры из query-string:
    • date_from/date_to — фильтр по датам start_estimation / end_estimation.
    • unit — фильтр по rlk.unit.
    • status — фильтр по RegInteractivOcenka.status_id.
    • kolesa2 — фильтр по page_kolesa.kolesa2_estimation (1 или 0).
  • Пагинация: 30 записей на страницу.

Что выводится в таблице

  • Дата оценки: end_estimation (если есть) иначе start_estimation.
  • Автомобиль/маркировка: вычисляется функцией _estimation_car_label (использует modification/mark/model/modification_name или fallback VIN/number_body).
  • Подразделение и статус: из estimation.rlk.unit и estimation.status.
  • 2КК: значение estimation.page_kolesa.kolesa2_estimation и флаг has_second_set (true если == 1).
  • Наличие приёмки: флаг has_reception + reception_id.
  • Действия:
    • Если приёмка существует → кнопка “Открыть” по /estimations/kolesa-reception/<reception_id>/.
    • Если приёмки нет и 2КК = да → кнопка “Создать” по /estimations/kolesa-reception/create/<estimation_id>/.

2) Создание приёмки: kolesa_reception_create

Что делает: создаёт (идемпотентно) запись RegInteractivOcenkaKolesaReception для выбранной оценки, но только если в оценке указан второй комплект колес.
  • Получает RegInteractivOcenka вместе с page_kolesa и rlk.
  • Проверяет: estimation.page_kolesa_id и estimation.page_kolesa.kolesa2_estimation == 1.
  • Дальше вызывает create_kolesa_reception:
    • Сначала ищет существующую приёмку по estimation (если есть — возвращает её).
    • Если приёмки нет — создаёт объект с rlk, estimation, date=now, user=request.user.
    • Заполняет поля приёмки из estimation.page_kolesa (через _copy_kolesa_to_reception).
  • Редирект на детальную страницу приёмки.

3) Детальная приёмка: kolesa_reception_detail

Что делает: показывает данные приёмки, позволяет сохранить отредактированные поля и прикреплять/удалять файлы.

GET-загрузка

  • Загружает RegInteractivOcenkaKolesaReception с select_related на всю “витрину” (estimation, status, unit, справочники и т.д.).
  • Загружает файлы приёмки:
    • RegRegInteractivOcenkaFilesKolesaReception.objects.filter(kolesa_reception=reception).order_by('-date','-id')
  • Передаёт в шаблон справочники для редактирования Select2: marks/widths/profiles/radii/seasons/disk_types и et_disks/dia_disks/psd_disks.

POST-обработка (важно: разные формы и action)

  • Если action == save_reception:
    • Берёт id выбранных элементов справочников из POST (mark_tyre/width_tyre/…/psd_disk).
    • Находит соответствующие сущности в refs и назначает на объект reception.
    • Сохраняет количества дисков/шин и kolesa_estimation.
  • Иначе (или дополнительно) вызывается обработчик файлов:
    • handle_kolesa_reception_files_post
    • Операции: action=upload (multipart upload) и action=delete (удаление по id файла).

Файлы приёмки: handle_kolesa_reception_files_post

  • delete: извлекает RegRegInteractivOcenkaFilesKolesaReception по photo_id и текущей приёмке, удаляет, пишет messages.
  • upload:
    • Читает request.FILES.getlist('photos').
    • Фильтрует только image/* (по content_type).
    • Создаёт запись файла: name, file, user, date=now.
    • Сразу генерирует миниатюру через _save_file_thumbnail (PIL) и сохраняет file_mini.
  • После успешной загрузки/удаления редирект обратно на текущую страницу.

Где эта логика используется в проекте

  • Список/создание/деталь 2КК доступны в веб-интерфейсе через routes estimations/urls.py.
  • Страницы используются для управления процессом приёмки второго комплекта колес для интерактивных оценок.
  • Поля приёмки (mark_tyre, radius, count_disk и т.д.) напрямую соответствуют полям модели RegInteractivOcenkaKolesaReception.
  • Загрузка файлов привязана к модели RegRegInteractivOcenkaFilesKolesaReception через FK kolesa_reception.

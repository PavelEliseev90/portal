Приложение: api

Назначение: централизованный слой endpoint-ов для интеграций и внешних клиентов (мобильные приложения, обмены, swagger/openapi, сервисные операции).

Общая структура (api/urls.py)

  • Документация API: /api/swagger/, /api/redoc/, schema-json.
  • Android API v1: префикс /api/a/v1/* (авторизация, список РЛК, оценка, отправка форм/фото).
  • Android API v2 (Flutter): префикс /api/a/v2/* (оптимизированные endpoint-ы).
  • Интеграции с 1С: /api/exchange/, /api/exchange_bu/ и сервисные методы.
  • Автосалон/склад/цены: /api/v1/* (refresh автомобилей, avtohub/zna и др.).
  • Обработка медиа/голоса/очередей: endpoint-ы для аудио/конвертации/распознавания/очередей.

Крупные блоки endpoint-ов

БлокПример endpointСмысл
Post/utility post_info/ Сервисные операции и внутренние API-вызовы.
Mobile v1 a/v1/login_in/, a/v1/rlk_eco/, a/v1/estimation_*_post/ Старая линия API для Android-клиента, покрывает шаги интерактивной оценки и работу с РЛК.
Mobile v2 a/v2/login_in/, a/v2/offline_sync/, a/v2/catalogs/* Новая/оптимизированная линия API для Flutter, включая offline sync и каталоги.
Swagger/OpenAPI swagger/, redoc/ Автогенерация документации и схема для интеграторов.
Автосалон v1 v1/refresh_new_cars/, v1/info_cars_organization/ Операции обновления/синхронизации данных автомобилей и связанных сущностей.
Интеграции и обмен exchange/, exchange_bu/, refresh_link_cars_exchange/ Обмен данными с внешними системами (в т.ч. 1С контуры).
Голос/очереди get_records_queue/, post_call_queue/ Фоновые конвейеры обработки записей/звонков (распознавание и маршрутизация).
Каталоги catalog_mark, catalog_model, catalog_modification Поставки каталожных данных, используемых в оценке/подборе.

Связки с другими приложениями

  • estimations/register: мобильные endpoint-ы чтения/записи этапов интерактивной оценки.
  • avtosalon: endpoint-ы обновления автомобилей, цен и данных аналитики.
  • documents: часть интеграционных endpoint-ов оперирует сущностями РЛК/документов.
  • refs: каталоги и справочники прокидываются в мобильные/API сценарии.

Примечание по детализации

В api/urls.py очень большой перечень endpoint-ов. Для полной энциклопедии следующим шагом можно сделать подстраницы: api_mobile_v1.html, api_mobile_v2.html, api_exchange.html с описанием каждого метода (входные параметры, модельные связи, side effects).

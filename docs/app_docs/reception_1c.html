Приём автомобиля и второй комплект колёс

Документ для портала и интеграции с 1С. UI: вкладка интерактивной оценки page=24. Отправка: HTTP POST на HS 1С с Type: "reception".

1. Где в портале

  • ECO / интерактивная оценка → вкладка Приём автомобиля (?page=24).
  • Шаблоны: lo/lo_v5.html, lo/lo_v4.html + include lo/partials/reception_page.html.
  • Логика: portal/apps/eco/reception.py, обработка в eco/views.py (doc).
  • Модель приёма АМ: RegInteractivOcenkaReception (OneToOne к RegInteractivOcenkaRLK, related_name page_reception).
  • Модель приёмки 2КК: RegInteractivOcenkaKolesaReception (FK на estimation).
  • Отдельный UI 2КК: /estimations/kolesa-reception/.

2. Сценарий страницы «Приём автомобиля»

  1. Открытие page=24.
  2. Если нет согласования цены после КД (page_soglasovanie.price_after_kd <= 0) — сообщение: «Приём невозможен. Нет согласования цены после КД.»
  3. Если цена после КД есть и карточки приёма ещё нет — кнопка «Проверить и принять автомобиль» создаёт RegInteractivOcenkaReception и максимально префиллит поля из оценки / документов / RLK / салона / внешнего осмотра.
  4. Если оценка со вторым комплектом (page_kolesa.kolesa2_estimation == 1 или kolesa2) — при создании приёма АМ автоматически создаётся и приёмка 2КК (если её ещё нет).
  5. Кнопки: Сохранить, Обновить в 1С (refresh_data=reception1c).
  6. Внизу страницы — блок второго комплекта колёс (создать / показать данные / ссылка на карточку 2КК).

4. Второй комплект колёс

Условие «оценка со 2КК»

  • estimation.page_kolesa.kolesa2_estimation == 1 или
  • estimation.page_kolesa.kolesa2 == true

Блок на странице приёма

  • Если 2КК есть, а приёмки нет — кнопка создать + превью полей из оценки.
  • Если приёмка есть — все поля приёмки, дата, автор, флаг отправки в ИБ колёс, фото, ссылка на /estimations/kolesa-reception/<id>/.

5. Контракт отправки в 1С

  • Триггер: кнопка «Обновить в 1С» на page=24.
  • Код: eco.reception.send_reception_1c → build_reception_1c_payload.
  • Маршрутизация как у оценки: Kors HS / Alfa HS по rlk.unit.ib.alfa.
  • Корневой признак: "Type": "reception" (не путать с "estimation").

Корневая структура JSON

{
  "Type": "reception",
  "Rlk": { ... },                 // DocRLKSerializer
  "Estimation": { ... },          // RegInteractivOcenkaSerializer
  "Soglasovanie": { ... } | null, // цена после КД и пр.
  "Info": { ... },                // RegInteractivOcenkaRLKSerializer
  "Reception": { ... },           // страница приёма АМ — обязательно
  "HasKolesa2": true | false,
  "KolesaReception": { ... } | null,  // приёмка 2КК, если создана
  "Kolesa2": { ... } | null           // снимок 2КК из оценки, если HasKolesa2
}

Что 1С должна обработать в первую очередь

  1. Reception — создать/обновить документ приёма автомобиля.
  2. Если HasKolesa2 == true:
    • предпочтительно брать фактическую приёмку из KolesaReception;
    • если KolesaReception == null — можно взять Kolesa2 как данные осмотра.
  3. Soglasovanie.price_after_kd — согласованная цена после КД (условие допуска приёма на портале).
  4. Rlk / Estimation / Info — контекст РЛК и оценки (uin, vin, подразделение и т.д.).

Ожидаемый ответ: HTTP 200. Статус пишется в Reception.sent_to_1c_status / sent_to_1c_at.
